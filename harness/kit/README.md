# Style kit

One theme, named variants per preset slot, and quality settings, shared by the DOM UI and Phaser. Test room: `/games/lab/?scene=Kit`. Agent rules: the `kit` skill.

## Parts
- **Theme** (`theme.ts`): the CSS theme files are the source: `--ui-*` tokens (`harness/ui/tokens.css`) plus `theme.css` (`--kit-*`: background, ink, paper, line width, ambient, effect palette). The default is greybox (a placeholder); `clean`, `pixel` and `fantasy` are samples, not styles to copy; a game's look is its own theme (`harness/ui/README.md`). `theme()` reads them as Phaser values (`c.accent` as 0xRRGGBB, `line`, `font.display`, `motion()` for tweens). Switching the `theme` slot sets `<html data-theme>`, so the UI restyles through CSS, and kit parts restyle on the change event.
- **Variants** (`variants.ts`): a slot holds named variants; its first variant is the default. A slot starts on the URL's `?v.<slot>=<name>`, else the game's `variants` config, else the default. Built-in slots: `theme`, `particles`, `lights`, `juice`, `look`, `music`, `titleLayout`, `titleMood`, `transition`, `resultsLayout`, `rim`.
- **Quality** (`quality.ts`): `low|medium|high` plus `shadows`, `lights` (cap), `particles` (multiplier), `glow` (bloom and particle halos). Defaults to high; saved per game; `?q=low` overrides it. Everything applies live except raising `lights` above the cap baked at the first lit render, which needs a reload (the dev sidebar offers one). There is no render-resolution setting: Phaser 4 always renders at the game size. `quality.set({ level: 'low' })` resets every toggle to that level's defaults, even for the current level; `quality.set({ shadows: false })` overrides one toggle and keeps the level.
- **Presets**: `particles.ts` (burst/trail/ambient, capped, additive halo), `lights.ts` (rig: ambient, radius, intensity, flicker; sets the light cap), `juice.ts` (shake/flash/zoom punch/hit-stop, small/medium/big), `look.ts` + `look.frag` (one-pass grade, vignette, scanlines, cheap bloom on the camera). Each file's top comment lists the lab facts it rests on.
- **Kit tab** (`harness/dev/kit-tab.ts`): every slot, the quality settings, and "export variants". It sits in the dev sidebar (`harness/dev/`): F10 opens it. It is on in `vite` dev and off in builds unless the URL has `?dev=1`.
- **Boot** (`boot.ts`): `bootGame()`: fonts, Phaser config, bridge, UI, key capture, scenes, dev sidebar, title screen and game menu. `?scene=Key` skips the title. Scenes are added after READY, not in the Phaser config (it would auto-start the first before the UI exists and ignore `?scene=`); the order is in the file's top comment.
- **Title screen and game menu** (`title.ts`, `menus.ts`, `menu-parts.ts`, `savefiles.ts`): see below.

## A game uses it
```ts
// main.ts
bootGame({ id: 'mygame', name: 'My Game', scenes: { Play }, start: 'Play', variants: { theme: 'pixel', look: 'crt' } });

// a scene's create()
const k = kit(this);
const L = k.lights;            // first, before anything lit renders
k.background(); k.look();
L.lit(this.add.image(x, y, 'hero')); L.add(x, y);
k.fx.burst(x, y, { color: 'danger' }); k.fx.trail(bullet); k.fx.ambient();
k.juice.hit('big');            // in update(): if (k.juice.frozen) return;
k.text(40, 40, 'Score', { size: 32 });
this.tweens.add({ targets: obj, y: 100, ...k.theme.motion() });
```
To pick a look: open the game or the Kit room, choose variants in the dev sidebar, press "export" and paste the result into `variants` (and `tunes`, below). `__game.kit` (games booted with `bootGame`) has `variants()`, `set(slot, name)`, `quality()` and `setQuality(patch)`.

## Title screen and game menu
`bootGame` shows a title (Continue when a save exists, New game, Load when the game saves, Options, Credits when given) over a live lit scene; in play, Esc opens the menu and pauses the scenes (the first play start in a page load shows a short Esc hint, top-right, for 4 s) (Main: buttons only, Resume, Save/Load, Exit to title; tabs Audio, Graphics, Controls). The title puts the name in the top corner (top centre in `center` and `bottom`), a larger first button (Continue, else New game) and, in the bottom left corner in every layout, a column with master volume centred above quality (low/medium/high buttons, no label; the volume sits over Medium), so they can be set right after load: volume is a pointed triangle ramp (quiet point at the left, full height at the right) with a square speaker handle as tall as the triangle under it (at least 22 px, so it stays grabbable) and the percentage riding above it (`volumeRamp` in `menu-parts.ts`, also the Audio tab's master row; a range input on top does mouse, touch and keys; the speakers are `harness/ui/glyphs/`). The Graphics tab keeps the labelled Quality row. `bottom` lifts its menu row to leave the corner free. Options has the detailed tabs. Volume and quality use the kit's audio and quality, so they persist. Esc is ignored while the level editor (F2) is on or a text field has focus; see Esc below. Test room: lab `Title` (`?scene=Title`); `__game.kit.menu` has `open()`, `close()`, `isOpen()`, `toTitle()`, `state()` (`playing` is true while any scene but the title runs, so `goto` from the title counts).
```ts
bootGame({ id, name: 'My Game', scenes, start: 'Play',
  actions: { left: ['A', 'LEFT', 'PAD_LS_LEFT'], jump: ['SPACE', 'PAD_A'] },   // input actions (below); Controls tab; none: no tab
  credits: ['Art: A', 'Code: B'],                                // Credits entry; none: no entry
  save: { save: (game) => ({ level }), load: (data, game) => game.scene.start('Play', data) },   // none: no Save, Load, Continue
  variants: { titleLayout: 'center', titleMood: 'fireflies' } });
```
- **Save:** `save(game)` returns JSON of the running game; `load(data, game)` must start the scene with it (it also runs for Continue from the title, so `create(data)` reads it). 3 save files (`count` to change), kept with `harness/save.ts`; Continue loads the newest. A game that saves itself (autosave, one slot) passes `auto: true` (no Save or Load in the menus, only Continue), its own `store` (`createSaveStore`, savefiles.ts: one instance that it also reads and writes, so the title sees what the game saved) and `wipe(game)` (New game erases the save: the title asks "Erase the save? Click again" when one exists, then calls it). Machinerra is the example (`hub/save.ts`, `main.ts`).
- **A game's own settings and menu entries:** `bootGame({ tabs: [{ id, label, build }], menuItems: [{ id, label, run }] })`: `tabs` come after Controls in the title's Options and the game menu; `menuItems` are buttons under Resume on the game menu's Main tab (the menu closes, then `run`). Machinerra's Oracle tab and guide entry are the example (`guideview.ts`). The settings dialog is 520 px wide: more than four tabs need the game's CSS to widen `.ui-dialog--wide`.
- **Opt-outs:** `titleScreen: false` starts straight in `start` (no Exit to title); `gameMenu: false` removes Esc and its hint. Prototypes (page path `/games/proto-*`) default to no title and keep the menu; the lab sets both to false (its own Lobby scene and `back()`, which is an `onEscape` handler).
- **Esc means one level up** (`escape.ts`; the one keydown listener is in `menus.ts`). A game registers `const off = onEscape(this, () => { ...; return true; })` for as long as its "up" applies (cancel selection, close a panel, back to its own menu). The handler returns `true` when it consumed Esc, otherwise `false` and the next older handler, then the kit, gets it. Handlers run newest first and are removed when the scene shuts down (or call `off()`). The kit acts only when none consumed it: in play it opens the game menu. While the menu is open Esc is the menu's before any handler: back a tab or level, then close. On the title screen (and the lab Lobby) Esc goes to `/games/index.html`, only on the dev server and only when the page is the top window. Tests: `escape.test.ts`.
- **Own background:** `bootGame({ titleArt })` draws the game's own scene in place of the hills (`TitleArt` in `menu-parts.ts`: `draw(scene)` returns its `objects`, an `update(time, delta, px)` and an optional `leave(go)` that plays when Continue or New game is chosen, the menu fading out, and calls `go` when done). Machinerra's zeppelin is the example (`titleart.ts`).
- **Slots** (dev sidebar, export into `variants`): `titleLayout` left | center | bottom, `titleMood` dust | fireflies | fog (lights, motes and sky from the theme's `--kit-fx-*`). Add a mood with `titleMoodSlot.add(name, { hue, sky, motes, lights })`.
- **Cost** (Intel UHD pane, lab Title probe, step + GPU readback): about +1 ms over an empty scene in every mood, at low and high quality; ~40 motes alive, 2 to 5 lights.
- The theme restyles both screens (`harness/ui/README.md`, System screens).

## Transitions and results (`transition.ts`, `results.ts`)
Test room: lab `Transitions` (`?scene=Transitions`); pick the look with its buttons or the dev sidebar's `transition` and `resultsLayout` slots, then export into `variants`.
```ts
transition(this, 'Play', { level: 2 });                      // cover, scene.start('Play', data), uncover
transition(this, 'Play', undefined, { at: pointer });        // iris closes on a point; { variant: 'wipe', ms: 300, onSwitch, onDone }
transition(game, 'KitTitle');                                // from the Game: every running scene stops first (Exit to title)
results(this, { title: 'Level complete', tone: 'win', subtitle,
  stats: [{ label: 'Score', value: 12450 }, { label: 'Time', value: 192, format: mmss, best: true }],
  actions: [{ label: 'Next', to: 'Play', data: { level: 2 }, primary: true, key: 'N' }, { label: 'Title', run: () => ... }] });
```
- **`transition` slot:** `fade` (default) | `wipe` (diagonal sweep that leaves on the far side) | `iris` (closes on `at`) | `blocks` (cells in random order) | `dissolve` (noise, burning edge). Cover colour is the theme's `--kit-bg`, the edge the accent; add one with `transitionSlot.add('slow-iris', { kind: 'iris', ms: 800, color: 'ink', edge: 'fx2' })`. `ms` is per half. One at a time (`transition` returns false while one runs); `prefers-reduced-motion` turns every look into a short fade.
- **How:** the cover is a small `<canvas>` in `#ui-sys` (32x18 cells for blocks, up to 480x270 for iris), filled on the CPU each frame and scaled by the browser. It covers the HUD and menus too, blocks clicks, keydowns (F-keys pass) and `inputFor` actions while up, survives `scene.start`, runs on the game step (`__game.step(n)` drives it) and costs ~0.1 to 0.4 ms per frame of JS on the pane's machine, no GPU pass (`transitionInfo().frameMs`). The reveal waits for the target's `create()` to finish. Maths and tests: `wipes.ts`.
- **Not done:** pushing the old scene off (`scene.transition` + camera `x`, in the lab Juice probe): the DOM HUD does not move with cameras. A real pixelate of the scene needs a snapshot or a camera filter on both scenes (a full-screen filter pass, ~1 to 9 ms in `performance-gpu.md`); `blocks` is the cheap stand-in.
- **Results:** `.ui-results` in `#ui` (removed when the scene shuts down), made of `.ui-panel`, `.ui-stat`, `.ui-btn`, `.ui-key`: the game's theme restyles it. Slot `resultsLayout`: center | left | banner (also live while open). Numbers count up row by row (~1 s for four; `count: false` skips); Enter, Space, Esc or a click finishes the count, and the buttons stay inert until it is done plus 250 ms, so a mashed key cannot press Retry. `to` runs `transition`, `run` calls your function, `key` is a shortcut shown as a hint. Tone `win` colours the title with the accent, `lose` with danger. Returns `{ root, ready, counted, skip(), close() }`.

## Input actions, key prompts, hints (`input.ts`, `bindings.ts`, `hint.ts`)
A game binds actions, not keys; players rebind them in the menu's Controls tab and use a gamepad; prompts and hints show whatever is bound. Test room: lab `Input` (`?scene=Input`); `__game.kit.input` has `state()`, `rebind(action, slot, token)`, `reset()`.
```ts
bootGame({ ..., actions: { left: ['A', 'LEFT', 'PAD_LS_LEFT'], right: ['D', 'RIGHT', 'PAD_LS_RIGHT'], jump: ['SPACE', 'W', 'PAD_A'], fire: ['MOUSE_LEFT', 'PAD_RT'] },
                 axes: { moveX: ['left', 'right'] } });

const input = inputFor(this);                  // any scene; one per game, read state is the same everywhere in a frame
input.down('jump'); input.pressed('jump'); input.released('jump'); input.axis('moveX');   // -1..1; input.value('left') is 0..1
keyLabel('jump');                              // 'Space', or the pad glyph ('A', or a cross on a PlayStation pad) once a pad was used last
el.innerHTML = promptHtml('Press {jump} to jump');   // <kbd class="ui-key">Space</kbd>; livePrompt(el, text) keeps it current
hint(this, hero, 'Press {jump} to jump', { until: 'jump', delay: 2000 });   // world prompt: after 2 s, gone for good once jump is pressed
```
- **Tokens:** keys by physical position (`'SPACE'`, `'W'`, `'LEFT'`, `'SHIFT'`, `'1'`; WASD stays WASD on AZERTY, labels ask the layout), mouse (`'MOUSE_LEFT'`, `_MIDDLE`, `_RIGHT`), pad buttons (`'PAD_A'` `_B` `_X` `_Y` `_LB` `_RB` `_LT` `_RT` `_BACK` `_START` `_LS` `_RS` `_UP` `_DOWN` `_LEFT` `_RIGHT`) and stick directions (`'PAD_LS_LEFT'`, `PAD_RS_*`; analogue). Each entry in an action's list is a rebindable slot; the Controls tab shows pad slots while a pad is connected. A new key another action already uses swaps with it.
- **Reading:** one sampler per game on `PRE_STEP`, so `pressed()` is not consumed (ask from anywhere, any number of times) and a tap shorter than a frame still gives one frame. An unknown action name throws. Keys typed in a text field are ignored; Esc is the menu's, not bindable.
- **Persistence:** only changed actions are saved (`<id>:input`, through `harness/save.ts`), so changing a default later reaches players who never touched it; a saved list whose slot count no longer matches the declaration is dropped.
- **Gamepad** is read with `navigator.getGamepads()` (standard layout, no Phaser config), not Phaser's gamepad plugin: that one is per scene and updates only while its scene runs, so it cannot give game-level state or rebinding while the menu pauses the scenes. Browsers list a pad only after a button press on the page. Mouse buttons count on the canvas only and are not captured by rebinding (declared defaults only). Not verified with real hardware.
- **Hints:** Phaser Text via `kit(scene).text` above a game object (followed) or `{ x, y }`. `until` is an action (pressed) or a predicate. The delay counts scene time. `id` makes a finished hint permanent across runs (`resetHints()` forgets); without it a new run shows it again. `{action}` follows rebinding and the keyboard/pad switch.
- The Controls tab (`controlsTab(game)` in `menu-parts.ts`) is also the title's Options tab; a probe or custom screen can mount it too. Rows use the action name ('moveLeft' reads 'Move left').

## Add a variant or a slot
- Variant of a built-in slot: `particleSlot.add('embers', { ...particleSlot.variants.clean, halo: 0.3 })`, or add it to the slot's list in its file if every game should get it.
- A game's own slot: `const layout = slot('layout', { left: {...}, right: {...} })`, read `layout.value` and react with `layout.on(fn)`. It appears in the panel and the export automatically.
- A theme: a game's own, in its folder; recipe in `harness/ui/README.md`.

## Tuning and gameplay variants (`tune.ts`)
Try gameplay values live, share the feel as a link, compare settings side by side. Example: the lab `Materials` probe (`wear`).
```ts
const t = tune(this, { speed: [200, 50, 600], dash: true, mode: ['orbit', 'chase'] });   // [default, min, max(, step)] slider, toggle, choice (first = default)
update() { body.speed = t.speed; if (t.dash) ...; }          // t.<name> is always current: read it in update(), never cache it in create()
const jump = slot('jump', { floaty, snappy });               // a mechanic as variants: slot() is not only for looks; read jump.value, react with jump.on(fn)
```
- A tune starts from `?t.speed=320` > `bootGame({ tunes })` > the default; names are global per game (a scene restart keeps the value). The dev sidebar's Tuning block changes them live and writes them into the address bar; "export" prints `tunes: {...}` to paste into `bootGame`. `__game.kit.tunes()` reads them, `__game.kit.tune('speed', 320)` sets one.
- **Compare:** `/harness/compare.html?game=<name>&a=<query>&b=<query>[&c=..&d=..]`, 2 to 4 live panes of one or several games, each with its own query: `a=scene=Play;t.speed=150;v.jump=floaty` (`;` stands for `&`; `game=<other>` inside a query picks another game). A pane's box shows its live query (follows its dev sidebar) and is editable (Enter reloads); the page URL follows, so copying it keeps the comparison. A click focuses a pane; "Mirror input" copies keyboard events from the focused pane to the others (keyboard only; the panes' title screens still need a click each, or add `scene=Play`).
- **Hot reload:** an edited `tune(...)` or `slot(...)` definition in a hot-reloaded scene applies its new default, range and variants (a tuned value stays). Code, level and asset edits restart only the scene they touch, with its state in `create(data.hot)`: `harness/hot/README.md`.
- **Hub:** `/games/index.html` has three sections: Games (each with the start of its skill and links to play, edit and compare), Lab (the probe groups; `/games/lab/?tab=<Group>` opens a Lobby tab) and Harness (components, mockups, compare, embed; Esc on those pages goes back to the hub).

## Audio
`audio.ts`: a music director and an sfx helper on Web Audio (`kit(this).audio` or `audioFor(game)`; one per game, so music keeps playing across scenes). Test room: the Music block in the Kit room; volumes are in the dev sidebar. Facts and gotchas are in the file's top comment.
```ts
// main.ts: files are fetched and decoded before the first scene (missing ones are warned about, not fatal)
bootGame({ ..., audio: { music: { calm: ['base', 'bass', 'drums'], tense: { stems: ['base', 'drums'], bpm: 128 } }, sfx: ['hit', 'coin'] } });

const a = kit(this).audio;
a.music.play('calm', { fade: 2 });          // equal-power crossfade; same track again does nothing
a.music.intensity(0.7);                     // stems fade in at their `at` (default: spread over 0..1); call it every frame if you like
a.music.stinger('drop', { at: 'bar' });     // one-shot on the next bar; beat drop: + a.music.intensity(1, { at: 'bar', fade: 0.05 })
a.sfx.play('hit', { vary: 0.1 });           // max 4 copies per sound, 24 in all, the oldest is cut; a.sfx.define('hit', { max: 2 })
a.sfx.group('chop', ['chop', 'chop2', 'chop3'], { max: 2, pitch: 0.8, vary: 0.08, reverb: 0.3, priority: 1 });
a.sfx.play('chop', { at: { x, y } });       // positional: distance fades (k^2), pans and muffles it; out of hearing it does not play
a.listener = () => hero; a.hearing = { near: 300, far: 1100 };   // default listener: the newest scene's camera centre
a.sfx.group('buzz', ['buzz'], { lod: 3, bed: 'swarm' });   // the 3 nearest play one by one, the rest swell a looping bed
a.cut('dawn', 'music/title/full', 0, 6, 0.4, 2.5);         // a stinger (or a single hit) cut from a loaded buffer
a.set({ music: 0.5 }); a.stopAll();         // master/music/sfx/muted are saved per game
```
- **Many sources, one sound** (`docs/design/design.md`): a **group** is one sound with variants (a shuffled bag: never the same twice in a row) and one voice cap for all of them (`max`), with its own `pitch`, `vary` (pitch spread), `gainVary`, `priority` (over the 24-voice cap the lowest goes first; a newcomer that outranks nothing does not play), `reverb` send (0..1; one convolver room for the game, `a.setReverb({ seconds, decay, damp })`; sounds ship dry), `duck` (it lowers every other sfx for `duckTime`: an Oracle line or an alarm cuts through), `density` (each voice already sounding makes the next quieter, 1/sqrt(n)), `offset` (start somewhere into a long sound), and a **level of detail**: `lod: K` plays the K nearest sources heard in the last `lodWindow` s one by one; the rest feed a looping `bed` whose gain follows sqrt(their count), easing up fast and down slowly (`sfx.quietBeds()` fades them). `sfx.state()` shows voices, skips and bed levels per group.
- **A room for a whole scene** (a cave, a tunnel): `a.room({ send, seconds, decay, damp }, ease)` makes every sfx also send `send` (0..1) to the reverb on top of its own, and swaps the reverb's tail for that room (a lower `damp` is darker); eased in over `ease` s (default 1.5). `a.room(null)` eases it out and gives the game's room back. Music is untouched; a game that never calls it hears no change. `audio.state().room` shows the send now.
- **Positional:** `play(name, { at: {x, y}, floor })`: gain `hearingGain` (1 within `hearing.near`, k² to 0 at `far`), pan by side (±0.7 at 700 px), a low-pass from 18 kHz up close to 1.2 kHz at the edge (`lowpassFor`); `floor` keeps a big event faintly audible. Below 2% it is skipped, not played.
- **Tone:** `music.tone({ lowpass, gain, detune, fade })` colours the playing music without touching where it is (eased with `setTargetAtTime`; it also applies to tracks started later): the cheapest way to follow a fight or a calm without ever interrupting a song (Machinerra: muffled and quieter when calm, open when a hornet is on screen, detuned only when the Controller runs low on oil).
- **Song (horizontal re-sequencing):** `a.song` plays one whole recording section by section (`songs` in the manifest, or `song.add(name, { key, bpm, offset, segments: [{ name, from, to, mood }], gain })`, bars from the first downbeat) and changes only where a section ends: the song's own next section if its mood is within 0.2 of the wanted one (then it simply continues, sample-exact), else the closest mood elsewhere, avoiding the last three played. `song.mood(v)` sets the wanted mood (ease it in the game; it is only read at section ends), `{ urgent: true }` cuts in at the next 4-bar phrase when the mood differs by more than 0.3, `song.goto('outro', { at: 'bar' })` jumps to a named section (`only`: never picked by mood; `end`: nothing follows). It keeps playing across scenes. For a finished track that must never break, prefer one looping track and `tone`: Machinerra tried stem layering (separated stems faded by game state: a cacophony) and then this player (section jumps felt like one track interrupting another). Trim a mastered song with `gain` (0.5) so the sfx have room.
- **Limiter:** a safety net at -6 dB (soft knee, ratio 12, 5 ms attack, 250 ms release) with a soft clip after it; `state().limiter` is its reduction in dB. Steady reduction means the mix is too hot: trim the song or the sounds, do not lean on the limiter (at -10 dB / 3 ms it pumped and distorted a mastered song's bass).
- **Music waits for its track:** `play` of a track that is not loaded yet starts it when `load`/`add` registers it (the last request wins); `load` adds a track once all its stems are decoded.
- **Pipeline:** source audio goes in `games/<name>/audio/` (wav, flac, aiff; same layout as below); `npm run audio -- <name>` encodes ogg (libvorbis q4) and an mp3 fallback into `public/audio/`, incrementally; the dev server runs it on a change (`harness/hot/assets-plugin.ts`). ffmpeg: PATH, `$FFMPEG`, or the `ffmpeg-static` dev dependency. Decoded ogg loops are sample-exact in Chromium (a 75.294 s loop decoded to 75.2941 s at 48 kHz), so stems cut on the bar loop without a gap.
- **Files:** `games/<name>/public/audio/music/<track>/<stem>.ogg` (stems of one track: same length, cut on a bar line, loop point = file end; lowest intensity first) and `public/audio/sfx/<name>.ogg`; `.mp3` is the fallback, but mp3 encoder padding makes loops click. Buffers from Phaser's `load.audio` also work, and `a.addBuffer(key, Float32Array, sampleRate?)` takes generated audio, a prototype's sfx without files: then `a.sfx.play(key)` (does nothing without an audio context). Tracks can also be declared with `music.add(name, { stems: [bufferKeys], bpm })`.
- **Timing:** `at: 'beat' | 'bar'` quantizes to the playing track's grid (needs `bpm`, else a bar is one loop), on the audio clock. `continue: true` on `play` starts the new track at the old one's loop position (same tempo and bar count).
- **`music` slot:** a variant can remap track names and trim the music bus: `musicSlot.add('b', { tracks: { area1: 'area1_alt' }, gain: 0.8 })`, then A/B in the dev sidebar. Variants added after boot ignore the URL's `?v.music=`; define them before `bootGame`.
- **Master** is Phaser's `sound.volume`, so Phaser's own sounds follow it, but only sounds played through `a.sfx`/`a.music` use the buses, the voice cap and the limiter.
- `__game.kit.audio.state()` (or `.level()`) shows context state, volumes, track, stems, voices and the output level, to check without ears. Not verified: mp3/ogg decoding here (wav was), Safari/iOS, a browser that really locks audio.

## Shaders (`shader.ts`)
Custom fragment shaders from GLSL alone: a screen/object **filter** or a **shader object** (a quad). It bakes in the Phaser 4 gotchas from the lab Shaders probe: the `#pragma phaserTemplate(shaderName / fragmentHeader)` lines and a precision line are added when missing; nothing is automatic in Phaser 4, so `uTime` (seconds), `uResolution` (px) and `uPointer` (0..1 of the canvas, y UP, already flipped) are supplied to any shader that declares them; the controller and render node share one name and register once; a uniform name that the GLSL does not declare is warned about (Phaser would silently read 0). A full-screen single-pass shader costs about 1 ms on an Intel UHD.
```ts
import { defineFilter, addShader } from '../../harness/kit/shader';   // frag = GLSL text, e.g. `import frag from './x.frag?raw'`
const Wobble = defineFilter({ name: 'Wobble', frag, uniforms: { uAmount: 0.02 } });
const f = Wobble.add(this, this.cameras.main.filters.external);        // or obj.filters.internal; f.u.uAmount = 0.1; f.active = false
const bg = addShader(this, { frag, uniforms: { uColor: [1, 0.5, 0] }, x: 640, y: 360, w: 1280, h: 720 });   // bg.u.uColor = [...]
```
Remember: `outTexCoord` and `gl_FragCoord` are GL oriented (y = 0 at the bottom); a Shader object breaks sprite batching (one draw call each). Example: `games/lab/src/scenes/gpufx/particlefield.frag`. Pure helpers (`prepareFragment`, `declaredUniforms`, `pointerUv`) are in `glsl.ts`, tested in `glsl.test.ts`.

## Lights (`lights.ts`)
`const L = kit(this).lights` in `create()`: a scene with a rig lights its art without opting in. Test room: lab `Lit` (`?scene=Lit`, keys on screen); raw Phaser probe: `Lighting`.
```ts
const L = kit(this).lights;
this.add.image(x, y, 'hero');           // lit: every Image, Sprite and TileSprite is, added before or after the rig
L.unlit(img);                           // opt out; also unlit by rule: blend mode other than NORMAL (glows), scrollFactor 0 (HUD)
L.lit(img);                             // force, whatever the rules say;  L.auto = false: only L.lit() objects are lit
const lamp = L.add(x, y, { color: 'danger', radius: 300, intensity: 2 });
```
- **Judged at the first render** after an object is added, so `setBlendMode` / `setScrollFactor` right after `add` count. Graphics, Shapes and Text are never lit (a lit Graphics is drawn invisible): draw once into a texture to light it (below).
- **Bake Graphics** (`bake.ts`): `bake(this, (g) => { g.fillStyle(0xffffff); g.fillCircle(40, 40, 36); }, 80, 80)` draws once into a canvas texture and returns an Image (origin 0,0, so a drop-in keeps its place), which the rig lights like any other; it also takes an existing Graphics (consumed) and `{ key }` to draw once and reuse across restarts. Fills, strokes and paths work, gradients do not (`generateTexture`). Bake once, not per frame. The title's hills are canvas Images already; only its sky is unlit.
- **Normal maps are automatic** (`normals.ts`): a texture without one gets one made from its alpha (blurred, then Sobel) the first time the rig lights it, so lights shade a bevel along the silhouette instead of a flat pool; opaque textures (floors) get none. `normalOptions` (`radius` px of bevel, `strength` steepness, `maxSize`, `on`), `setNormalMaps(false)` switches them off live, `ensureNormalMap(tex, { force: true })` after redrawing a CanvasTexture. The map is capped at 512 px on its long side (it may be smaller than the texture). Generation, once per texture (Intel UHD pane): 64 px 1 ms, 128 px 3, 256 px 8, 512 px and bigger about 35 to 40 (an atlas of 2048 costs one 40 ms hitch at its first lit object, per page); no measurable render cost. A texture swapped in later by `setTexture` is not covered until `L.lit(obj)` or `ensureNormalMap` is called on it.
- **Pool and self-shadow defaults:** `L.add` puts the light at height 0.45 x radius (`{ height }` overrides; Phaser's own 0.1 lights only a small dot on flat ground). Self-shadow is off (`L.selfShadow = true` turns it on, still gated by `quality.shadows`): its threshold reads pixel brightness, so dark art goes black.
- **Rim light** (`rim.ts`, `material.frag`, slot `rim`: soft (default) | off | bright, forced off on quality low): a subtle edge on the side of each lit sprite facing a light, in the light's colour tinted toward the art's (so unmarked art does not read as metal). The slot is a global strength; the sprite's material shapes it (below): only metal and paint get a bright edge. `bright` is the opt-in strong one. Needs the automatic normal maps (a flat normal has no edge). It swaps Phaser's `ApplyLighting` shader addition for a rim one (`rim.frag`, the cheap shader every lit game starts on; once art gets a material it becomes the material shader, below), so no extra draw or pass. Keys: lab `Lit` R, `Lighting` M. `setRim(game, 0.8)` sets any strength, live.
- **Materials** (`material.ts`, `wear.ts`, `normals.ts`; lab probe `Materials`): what a surface is made of decides how it shines and how its rim falls off. `material(img, 'metal', { wear: 0.5 })`, or `L.lit(img, 'wood')`, or `bake(this, draw, w, h, { material: 'stone' })`. Presets `metal`, `wood`, `stone`, `cloth`, `skin`, `painted`; `matte` (the default: the plain rim); or numbers: `material(img, { base: 'metal', gloss: 0.6, bevel: 1.2, wear: { scratch: 2 } })`.
  - **What a material is:** `gloss` (specular strength and tightness; rim sharpness and brightness), `metal` (specular and rim take the art's colour instead of the light's), `bevel` (width of the rounded edge: metal 0.8x is a tight hard edge, wood 2.2x and cloth 2.6x a wide soft one), `relief` (the art's own darkness is read as depth: dark lines become grooves, and dull the shine), `wear` mix (`scratch` fine grooves, `stain` dull blotches, `dent` round dips, `flake` chipped patches; `opts.wear` scales the mix or sets kinds), `emissive` (high quality: glows at its own colour whatever the lights do: `emissive: { amount: 1, where: 'bright' }` or a mask function).
  - **Defaults from the art pipeline:** a `material` in an `art/sizes.json` rule (`"weapons/": { "height": 64, "material": "metal" }`, or `{ "material": { "preset": "wood", "wear": 0.6 } }`; same matching as sizes) is written into each matching frame's atlas entry, and `loadAtlas` assigns it to that frame, so art gets a material without anyone calling `material()`. These are defaults, not rules: `material(img, ...)` or `L.lit(img, spec)` on any object overrides its frame whenever you see fit, and `material(texture, ...)` replaces every default of the atlas. A material belongs to a frame, so objects sharing a frame share it. Frames with no rule cost nothing, and the plain rim shader stays until the first frame with a material is loaded.
  - **Per material** (rim strength `soft` = 0.6; the rim's brightness is `strength x gain x tilt^exponent`, specular is `gloss^2 x (0.4 + 0.4 metal) x 1.2`). Only metal and paint shine; wood, stone, cloth and skin have a faint, wide rim in the art's own colour and no visible specular, so they read as matte. The plain rim (art with no material) is the matte row.

    | material | gloss | bevel | rim gain | rim exponent | specular | rim colour |
    |---|---|---|---|---|---|---|
    | metal | 0.9 | 0.8 | 4.0 | 3.7 (thin, sharp) | 0.78, tight | art colour, bright |
    | painted | 0.5 | 1 | 1.2 | 2.5 | 0.12, soft | between art and light |
    | skin | 0.14 | 2 | 0.37 | 1.4 | 0.01 | art colour |
    | wood | 0.06 | 2.2 | 0.31 | 1.2 | 0 | art colour |
    | stone | 0.04 | 1.8 | 0.31 | 1.1 | 0 | art colour |
    | cloth | 0 | 2.6 | 0.30 | 1 (wide) | none | art colour |
    | matte, plain rim | 0 | 1 | 0.30 | 1 | none | art colour |

  - **How:** the shine rides in the normal map's ALPHA (255 = none, so artist normal maps and the flat default are neutral); the lit shader turns it into specular and the rim shape. Wear and relief are added to the height before the normals are taken, so lights catch every scratch, and they dull the shine where they cut. All in the one lit pass: no extra draw, pass or object. Maps are made when the texture is first lit (or at `material()` if later), from the texture name as seed: same art, same wear. `material(texture, ...)` covers every frame, `material(img, ...)` only its frame (an atlas gets a material per frame, built per frame region). A texture with an artist-supplied normal map keeps it (no material). An opaque texture with a material gets maps too (a stone floor: wear and relief, no silhouette bevel; wear does not tile).
  - **Quality:** the material shader costs more than the plain rim, so a game runs the plain rim until its first `material()` / `L.lit(obj, spec)` / `bake(..., { material })`, then switches live. Low = Phaser's own lit shader (maps still shade, no rim or specular), medium = the material shader (shine from alpha), high = also a second texture beside the normal map: R occlusion (wear dirt darkens it), G roughness, B metalness, A emissive (the glTF ORM layout plus emissive), bound in a third texture slot (batching unchanged: the pair is picked by the normal map, which already splits the batch). ORM maps are made only for textures with a material (the rest share a neutral texel), and the ORM shader runs once one exists. Emissive needs high; on medium make glowing parts a separate unlit overlay sprite. `setMaterials({ on, wear, orm, gain })` (live; rebuilds every map, a few ms each): `on: false` = every map neutral, the comparison switch; `setMaterialRim(game, false)` = the plain rim on every material.
  - **Cost** (Intel UHD pane; machine load drifted by 2x between sessions, so read ratios): per texture, maps cost about 1.2 to 1.5x the plain normal map without wear, about 1.5 to 2x with wear, ORM adds 10 to 20% more (plain map was 64 px 1 ms, 128 3, 256 8, 512 35 to 40 on a calm machine; a 512 px map with wear is about 70 to 80). Shader, 6 screens of lit fill at 8 lights: +2.6 to +4 ms over Phaser's lit shader at medium, +3.4 to +5 at high, the same with or without materials on the art; the plain rim shader was +0 to +1.6. In a typical 1 to 2 screens of lit fill that is about +1 ms. Wear fields alone are about a third of the generation time.
- **Cost** (Intel UHD pane, 240 small images ~1.5 screens of fill, 3 lights, cap 32, min of runs; shared machine, read ratios): all lit +2.6 ms over all unlit. Lit and unlit objects use different shader paths and each switch breaks the batch: lit/unlit alternating by depth cost +3 to +6 ms more than the same objects grouped (about 0.015 ms per extra draw call). Default-lit makes whole layers lit, so the cost to watch is unlit effects drawn between lit sprites by depth: give effects their own depth band.

## Collision shapes from art (`collision.ts`)
Outlines traced from a sprite's image, for Matter bodies (Arcade takes one box or circle). Shapes are in SOURCE IMAGE PIXELS (top-left origin): multiply by the sprite's scale. Probe: lab `Collision`; its top comment holds the measured table (one angular, white-and-black figure).
```ts
const set = shapesFromTexture(this.textures, 'hero', { budgets: [16] });   // once at load; cached per key + options
addMatterImage(this, 'hero', set.polys[16], x, y, 0.2);                    // concave outline -> Matter body, sprite aligned
applyArcadeBox(sprite.body, set.core);                                     // or applyArcadeCircle(sprite.body, set.circle)
```
- **Pick:** auto with a reviewed overlay: build 16 vertices when the art lands, look at the overlay (or the JSON) once, ship it: no agent time, about 1 ms per Matter body to create, ~80% of the silhouette (IoU). Take 32 when contact accuracy shows (~93%, twice the convex parts); 8 is too coarse (~65%). An Arcade box (`core`) for Arcade games or many bodies; the hull for convex pickups. Hand-author only when the hitbox is a design choice (smaller hurtbox, ignoring spikes, a fat grab shape), starting from the auto polygon's JSON.
- **How:** image -> mask (alpha, or flood fill from the edges for opaque paper) -> low-res -> marching squares -> Douglas-Peucker bisected to the vertex budget (+ hull, Arcade box and circle). All budgets for a 1.3 MP image take 100-300 ms at load, mostly reading pixels and the flood fill. `ShapeSet` is plain JSON: `JSON.stringify(set)` and commit it next to the art to skip that.
- **Gotchas:** `addMatterImage` takes source-px verts (Matter scales the body with `setScale`; pre-scaled verts came out 10x too small) and sets Matter's `minimumArea` to 1. Not covered: leaky line art (a gap lets the flood fill into the figure, which loses its interior), art with several parts or real holes (only the largest contour is used), SVG (rasterise it to a canvas texture first).

## World
`createWorld(scene, { width, height })` (`world.ts`, standalone because it needs the level size): grid cull with near-camera logic (`cull.add`, `cull.forNear`; far Arcade bodies leave the physics world), pools that release off-screen objects (`pool`), baked or fading marks and dirty-feet footprints (`marks`), remains that decay and bake a smudge (`remains`), blob shadows following `quality.shadows` (`shadows`; a game's own shape and colour: `add(obj, { key, tint })`, `shadows.tint`; a thing lifted by its own drawing: `Shadow.raise`; a light that is not the world's: the `shadows.lean` hook), and `w.stagger(every, fn)`: logic for far or idle entities once per N frames each, spread over frames (near ones go in `cull.forNear`). Arcade only; main camera only. Demo: lab scene `World`.

## Art atlas (`assets.ts`)
Drop the artist's PNG/WebP (any size, folders allowed) in `games/<name>/art/`; the dev server (or `npm run assets -- <name>`) resizes each to its on-screen size (`art/sizes.json`: default max side, per file/folder/glob `height`/`width`/`max`, `scale: 2` for crispness, `pixel` for pixel art), trims transparent borders and packs one atlas into `games/<name>/public/assets/` (rebuilds only on change). A rule can also carry a `material` (`"material": "metal"` or `{ "preset": "wood", "wear": 0.6 }`): a default surface for those frames, applied by `loadAtlas` and overridable in code with `material()` (see Materials). Frame name = path without extension. In a scene: `preload() { loadAtlas(this) }`, then `const art = atlas(this); art.anims(); art.sprite(x, y, 'hero/idle-01').play('hero/idle')` (numbered runs become animations; `art.image/sprite` undo a 2x store). Format and options: top of `scripts/assets.mjs`. Demo and before/after memory: lab scene `Assets`.

## Random (`rng.ts`)
Seeded randomness for game logic (plain TS, no Phaser). Same seed, same run; `fork(label)` gives a system its own stream; `state` saves and restores the sequence. mulberry32 with cyrb53 seed hashing; the seed is a number or string.
```ts
const r = rng('level-3');                       // int(min, max) inclusive, range, chance(p), pick(list), weighted([[item, w]]), shuffle(list) (copy)
const spawns = r.fork('spawns');                // draws from spawns do not move r; the same label gives the same stream
const saved = r.state; r.state = saved;         // save game: store the number, assign it back to resume
```
Tests: `rng.test.ts`.
